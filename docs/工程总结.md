### Version 2.53 - IME Native Input Path Cleanup (2026-04-14)

**Bug Fix — Remove the Last Remaining Chinese Punctuation Double-Input Path:**

After v2.52, the terminal punctuation workaround was already much narrower, but one final duplication case still remained in practice: entering a single Chinese punctuation symbol like `，` could still occasionally produce two characters.

The safest fix turned out to be removing the last manual resend behavior entirely and trusting the native terminal input path:

- Deferred punctuation state is still used to suppress duplicate keyboard events for the same key
- But the app no longer attempts to synthesize or resend punctuation itself
- Native xterm/browser input is now treated as the sole source of truth for the committed punctuation character
- As soon as native `input` or xterm `onData` arrives, the deferred state is cleared

This keeps the earlier IME compatibility work in place while eliminating the final duplicate-symbol path.

**Files Changed:**
- **Frontend**: `frontend/src/components/terminal/Terminal.tsx`
- **Documentation / release metadata**: `README.md`, `docs/工程总结.md`, `wails.json`

**Key Lessons:**
- For embedded-terminal IME fixes, every extra synthetic write path increases the chance of double input.
- Once the native input path is confirmed reliable, the best workaround is often to remove fallback emission entirely and leave only event suppression/state cleanup.

## 🔥 Latest Update (2026-04-14)

### Version 2.52 - IME Punctuation Duplication Fix (2026-04-14)

**Bug Fix — Prevent Double-Sending Chinese Punctuation in Terminal Apps:**

The first macOS IME punctuation fix in v2.51 correctly restored full-width Chinese punctuation inside terminal applications, but one follow-up bug remained: a single punctuation keystroke could still arrive twice.

The cause was the hybrid workaround path:

- The browser/xterm native input flow was already committing the punctuation once
- The app-level `beforeinput` handler also wrote the same committed punctuation directly to the PTY
- As a result, one input like `，` could become `，，`

The terminal now narrows the workaround so only the fallback path performs a manual PTY write:

- `beforeinput` no longer sends committed punctuation to the PTY a second time
- Native committed input is treated as the source of truth when it arrives
- The pending punctuation marker is simply cleared
- The `keyup` fallback remains in place for edge cases where the native committed event never arrives

This preserves the original IME compatibility fix while removing duplicate punctuation output.

**Files Changed:**
- **Frontend**: `frontend/src/components/terminal/Terminal.tsx`
- **Documentation / release metadata**: `README.md`, `docs/工程总结.md`, `wails.json`

**Key Lessons:**
- For IME input workarounds, the safest fix is usually to minimize the number of paths that can emit text into the PTY.
- When a browser-native input path already commits the correct text, custom handlers should usually observe and clear state rather than re-send the same data.

### Version 2.51 - Terminal Input & Status Bar Fixes (2026-04-14)

**Bug Fix — macOS Chinese IME Punctuation in Terminal Apps:**

After entering the embedded terminal and launching CLI tools like `codex`, users could type Chinese characters with the macOS IME, but punctuation often arrived as plain ASCII punctuation instead of full-width Chinese punctuation. The bug was specific to punctuation keys in `WKWebView`/xterm event flow rather than shell locale handling.

The terminal now routes macOS punctuation keys through a deferred input path:

- Plain punctuation keys are held back from xterm's normal ASCII `keydown` path
- The app waits for the browser's committed `beforeinput` text payload
- That committed text is written directly to the PTY, preserving full-width punctuation like `，。！？；：`
- A small `keyup` fallback keeps normal English punctuation working if the browser does not emit the expected committed-text event

This keeps terminal shortcuts intact while making Chinese punctuation input behave naturally inside terminal applications.

**Bug Fix — Cross-Page Terminal Copy Reliability Regression:**

The previous multi-page terminal copy fallback had regressed in a subtle way: selection snapshots were only refreshed on `select-to-copy`, and any non-empty DOM selection text could suppress the fallback even when the selection still lived inside the terminal itself.

The copy pipeline now behaves more robustly:

- Terminal selection snapshots are refreshed on every xterm selection change, not only during auto-copy
- Native copy fallback checks whether a DOM selection is actually outside the terminal before suppressing the cached selection path
- Long drag selections across scrollback once again copy correctly with standard copy actions

This restores the intended v2.47 behavior without broadening clipboard interception outside terminal scope.

**UI Fix — Single-Line SSH Status Footer with Hover Detail:**

The SSH server info footer below the terminal could previously consume two visual rows on narrow windows, and an intermediate attempt to lock it to one row introduced horizontal scrolling. The footer now uses a single adaptive row instead:

- The seven status pills are laid out in a fixed single-row grid
- Labels and values shrink with ellipsis rather than wrapping
- Hovering any pill or value still reveals the full content via tooltip/title text
- The footer remains compact and visually stable at the bottom of the terminal pane

**Files Changed:**
- **Frontend (terminal input/copy)**: `frontend/src/components/terminal/Terminal.tsx`, `frontend/src/components/terminal/terminalCopy.ts`, `frontend/src/components/terminal/terminalCopy.test.ts`, `frontend/src/components/terminal/terminalIme.ts`, `frontend/src/components/terminal/terminalIme.test.ts`
- **Frontend (status footer UI)**: `frontend/src/components/terminal/Terminal.css`
- **Documentation / release metadata**: `README.md`, `docs/工程总结.md`, `wails.json`

**Key Lessons:**
- IME bugs in embedded terminals often happen at the browser event-routing layer, not in PTY locale setup.
- Terminal copy fallbacks should reason about where the selection lives, not just whether the page currently reports any selected text.
- Compact status bars work best when they degrade with truncation + hover detail instead of wrapping or introducing secondary scroll regions.

### Version 2.50 - macOS Terminal Renderer Stability (2026-04-13)

**Bug Fix — Prefer DOM Renderer on Apple WebViews:**

Some macOS terminal sessions could intermittently show visual corruption inside the embedded Wails window: stray colored glyph fragments, partially overdrawn characters, or small text shards lingering after the terminal repainted. The issue looked like "乱码", but it was not coming from UTF-8 decoding or shell locale handling. It was a renderer-layer problem.

To make the terminal stable, Apple platforms now prefer xterm's built-in DOM renderer instead of the accelerated WebGL/Canvas path:

- macOS terminals in `WKWebView` no longer rely on the GPU renderer by default
- Windows keeps its existing special-case behavior for local terminals
- Linux and other non-Apple environments still use accelerated rendering as before

This intentionally favors visual correctness over GPU acceleration on Apple embedded webviews, which is the right tradeoff for a terminal app.

**Implementation — Platform-Aware Renderer Selection:**

The renderer selection helper in `frontend/src/utils/terminalRenderer.ts` now distinguishes between:

- **Apple platforms** -> `dom`
- **Windows local terminals** -> `dom`
- **Other environments** -> `accelerated`

`frontend/src/components/terminal/Terminal.tsx` continues to load WebGL first only when the renderer strategy returns `accelerated`, and its log output now reflects the generic DOM-renderer fallback path more accurately.

**Regression Coverage:**

`frontend/src/utils/terminalRenderer.test.ts` now includes:

- Apple platform detection tests
- A regression test asserting macOS terminals use the DOM renderer
- A non-Apple Linux case to ensure accelerated rendering still stays enabled where intended

**Files Changed:**
- **Frontend**: `frontend/src/components/terminal/Terminal.tsx`, `frontend/src/utils/terminalRenderer.ts`, `frontend/src/utils/terminalRenderer.test.ts`
- **Documentation / release metadata**: `README.md`, `docs/工程总结.md`, `wails.json`

**Key Lessons:**
- Terminal "乱码" screenshots are not always encoding failures; embedded GPU renderers can corrupt glyph output while the underlying text stream remains correct.
- In desktop webviews, conservative renderer defaults are often more valuable than raw rendering speed.
- Small platform-detection helpers are worth testing directly because they control high-impact runtime behavior.

### Version 2.48 - SSH Config Save Formatting & Repository Cleanup (2026-04-09)

**New Feature — Auto-Format SSH Config on Save:**

When users save `~/.ssh/config` through the built-in editor, the app now automatically inserts a blank line between neighboring `Host` blocks. This makes large SSH config files noticeably easier to scan, especially when the file contains many servers managed directly from the sidebar and editor.

The formatting rule is intentionally conservative:

- It adds **one blank line between server blocks**
- It keeps **comments and directives inside a block** attached to that block
- It does **not** reorder fields within each server entry
- It applies to both **local** and **remote** SSH config saves through the same backend path

**Implementation — Shared Save-Time Formatter in Backend:**

The save pipeline in `internal/app/app.go` now checks whether the file being written is an SSH config path. If so, it runs the text through `formatSSHConfigSpacing()` before writing:

- `WriteLocalFile()` formats local `~/.ssh/config` saves
- `WriteRemoteFile()` formats remote `.ssh/config` saves when edited through the app

The formatter itself lives in `internal/app/ssh_config_format.go` and works by:

1. Splitting the file into a prefix section plus `Host` blocks
2. Trimming extra blank lines around each block
3. Joining blocks back together with exactly one blank line
4. Preserving the original trailing newline when present

This keeps the behavior predictable and avoids over-formatting unrelated SSH config content.

**Repository Cleanup — Remove Tracked `.DS_Store`:**

The repository already ignored `.DS_Store`, but previously committed Finder metadata files were still hanging around in Git history as tracked files. This release removes those tracked `.DS_Store` entries so future macOS Finder noise stays out of normal diffs and release commits.

**Files Changed:**
- **Backend**: `internal/app/app.go`, `internal/app/ssh_config_format.go`, `internal/app/ssh_config_format_test.go`
- **Repo hygiene / release docs**: `.gitignore`, `README.md`, `docs/工程总结.md`, `wails.json`

**Key Lessons:**
- Formatting at save time is often the most reliable place to enforce readable config structure because it covers every UI path automatically.
- SSH config cleanup should stay narrow and predictable; spacing normalization helps readability without surprising users by reordering or rewriting all directives.
- Git ignore rules alone do not fix already-tracked junk files; tracked metadata must be removed from the repository once.

### Version 2.47 - Server Ordering & Terminal Copy Reliability (2026-04-09)

**New Feature — Sortable SSH Server Sidebar:**

The SSH server list on the far left is now fully orderable instead of being locked to a backend-generated alphabetical list:

- **One-click ascending / descending sort** buttons reorganize the server list by alias name
- **Direct drag-and-drop reordering** lets users arrange servers manually in the sidebar

- The sort/reorder flow works with the existing search box, so filtered drag operations still update the full underlying order correctly

This turns the sidebar into a real SSH config organizer rather than a read-only projection of host aliases.

**Implementation — Preserve and Rewrite Real SSH Config Order:**

Two pieces were needed to make ordering reliable:

1. **Backend order preservation**
   - `GetSSHConfig()` in `internal/app/ssh_config_resolver.go` no longer calls `sort.Strings(aliases)`
   - Alias discovery now stays in file order (including inline `Include` expansion order), so the frontend receives the same sequence that exists in the SSH config

2. **Frontend config rewrite support**
   - Added `frontend/src/utils/sshConfigOrdering.ts` to parse SSH config text into a prefix + `Host` blocks
   - Reordering keeps global directives before the first `Host` block intact
   - Multi-alias `Host` lines stay grouped as a single block during reorder
   - After drag/sort, `TerminalTab.tsx` reads `~/.ssh/config`, rewrites the block order, and saves it through the existing Wails file API

**Bug Fix — Long Terminal Selection Copy Reliability:**

The terminal copy flow on macOS and native copy actions had a subtle failure mode: when users selected text across multiple screens of scrollback and then triggered the app-level copy action, xterm could momentarily lose the live selection string even though the terminal still visually showed a selection.

The terminal now keeps a short-lived **selection snapshot cache**:

- When users select/copy text in the terminal, the latest selection is remembered briefly
- Native `copy` handling first checks the live xterm selection, then falls back to the recent snapshot when appropriate
- Copy is suppressed when the active target is an editable control or a normal DOM text selection outside the terminal

This keeps multi-page copy working without stealing copy behavior from editors, inputs, or other UI elements.

### Version 2.44 - SSH Auth Overhaul & Terminal UX Fixes (2026-04-01)

**New Feature — Full OpenSSH Config Resolution:**

The old SSH host parsing only handled a few flat fields from `~/.ssh/config`. It could list simple aliases, but it ignored many real-world OpenSSH behaviors such as recursive `Include`, system-level `/etc/ssh/ssh_config`, `ProxyJump`, `ProxyCommand`, `IdentityAgent`, `UserKnownHostsFile`, `UseKeychain`, `AddKeysToAgent`, `ForwardAgent`, and `IdentitiesOnly`.

This version introduces a dedicated resolver built on `github.com/kevinburke/ssh_config`:

- Resolves effective host settings from both user and system SSH config
- Recursively scans `Include` files to build the server list shown in the sidebar
- Supports multi-hop connection flows via `ProxyJump`
- Supports `ProxyCommand` socket creation
- Honors per-host `UserKnownHostsFile` instead of hardcoding `~/.ssh/known_hosts`
- Preserves OpenSSH-style token expansion for `%h`, `%p`, `%r`, `%n`, `%d`, etc.

**New Feature — macOS Keychain + ssh-agent + Private Key Passphrase Flow:**

SSH authentication on macOS is now much closer to native OpenSSH/MobaXterm behavior:

- **Passwords** for password-only hosts are cached in **macOS Keychain**
- **Encrypted private key passphrases** are also cached in **macOS Keychain**
- When cached credentials fail, the app clears the invalid cache entry and prompts again
- `ssh-agent` signers are loaded from `SSH_AUTH_SOCK` / `IdentityAgent`
- If `AddKeysToAgent` or `UseKeychain` is enabled, parsed private keys are added back to agent when possible
- Interactive terminal sessions now honor `ForwardAgent yes`

For non-macOS builds, the same API falls back to the app-local secret cache file so the code path stays consistent.

**Bug Fix — Password-Only Hosts and Terminal UX:**

This release also rolls in the terminal and session fixes completed alongside the SSH refactor:

- **Password-only SSH hosts** now connect properly and prompt for password instead of silently failing when no key is configured
- **Ctrl+left-click** on macOS now opens terminal URLs correctly
- **Selected terminal text** can be copied reliably through native copy handling
- **Server sidebar** now scrolls, so long server lists no longer become unreachable

**Files Changed:**
- **Backend (new)**: `internal/app/ssh_config_resolver.go`, `internal/app/ssh_connection_helpers.go`, `internal/app/ssh_secret_store_darwin.go`, `internal/app/ssh_secret_store_fallback.go`
- **Backend (modified)**: `internal/app/ssh.go`, `internal/app/ssh_manager.go`, `internal/app/terminal_handler.go`
- **Frontend**: `frontend/src/components/terminal/Terminal.tsx`, `frontend/src/components/terminal/TerminalTab.tsx`, `frontend/src/components/terminal/TerminalTab.css`
- **i18n / bindings**: `frontend/src/i18n/locales/en-US/terminal.json`, `frontend/src/i18n/locales/zh-CN/terminal.json`, regenerated `frontend/wailsjs/`
- **Docs / release**: `README.md`, `docs/工程总结.md`, `AGENTS.md`, `wails.json`, `build-release.sh`

**Key Lessons:**
- SSH config support is not just a parser problem; connection setup, auth retries, known_hosts handling, and terminal session startup all need to share the same resolved config.

- `ForwardAgent` only matters for interactive SSH sessions after connection is established, so the forwarding setup belongs in terminal session startup, not just connection creation.

### Version 2.41 - Editor Visibility Fix (2026-02-28)

**Bug Fix — Editor Pane Invisible/Uneditable:**

Root cause: In `EditorTab.css`, `.editor-pane` sets `visibility: hidden` and `pointer-events: none` to hide inactive editor panes. However, `.editor-pane-active` only overrode `display: flex` without restoring `visibility` and `pointer-events`. Since both selectors have equal CSS specificity and the undeclared properties inherit from `.editor-pane`, **all** opened files appeared blank and unresponsive to input — Monaco Editor was loaded and functional underneath but invisible.

Fix: Added `visibility: visible` and `pointer-events: auto` to `.editor-pane-active`:
```css
.editor-pane-active {
  display: flex !important;
  flex-direction: column;
  visibility: visible;
  pointer-events: auto;
}
```

**Files Changed:**
- **Frontend**: `frontend/src/components/editor/EditorTab.css` — Added visibility/pointer-events restore (+2 lines)

**Key Lessons:**
- When using `visibility: hidden` to hide inactive panes, the active pane class **must** explicitly restore `visibility: visible` — CSS does not auto-override undeclared properties
- The bug affected all file types equally, not just `.ovpn`; symptoms: file tab appears with correct name but editor area is blank/unresponsive

## Previous Update (2026-02-28)

### Version 2.40 - Chinese/CJK Input Fix (2026-02-28)

**Bug Fix — Terminal Chinese/CJK IME Input Garbled:**

Root cause: `attachCustomKeyEventHandler` in `Terminal.tsx` was processing keydown events during IME composition without checking `event.isComposing` or `event.keyCode === 229`. This interfered with xterm.js internal `CompositionHelper`, causing Chinese input to be garbled in both display (echo) and execution.

Fix: Added IME composition guard at the top of the custom key handler:
```typescript
if (event.isComposing || event.keyCode === 229) {
  return true  // Let xterm.js CompositionHelper handle IME events
}
```

**Bug Fix — Windows Terminal UTF-8 Output Truncation:**

`pty_windows.go` was missing `UTF8SafeBuffer` for output reading. When `Read()` splits a multi-byte UTF-8 character at buffer boundary, `string(buffer[:n])` creates invalid UTF-8, causing garbled output. Fixed by adding `UTF8SafeBuffer` (matching `pty_unix.go` pattern) with `AppendAndFlush()` and deferred `Flush()`.

**Enhancement — SSH Terminal UTF-8 Locale:**

Added `Setenv("LANG", "en_US.UTF-8")` and `Setenv("LC_ALL", "en_US.UTF-8")` after SSH PTY request. Most SSH servers reject `Setenv` for security, so errors are silently ignored. This helps when the remote server has a non-UTF-8 default locale.

**Files Changed:**
- **Frontend**: `frontend/src/components/terminal/Terminal.tsx` — IME composition guard (+8 lines)
- **Backend**: `internal/app/pty_windows.go` — UTF8SafeBuffer for Windows ConPTY output (+13 lines)
- **Backend**: `internal/app/terminal_handler.go` — SSH session UTF-8 locale env vars (+7 lines)

**Key Lessons:**
- xterm.js `attachCustomKeyEventHandler` runs BEFORE internal `CompositionHelper.keydown()` — must explicitly skip IME events
- `event.isComposing` and `event.keyCode === 229` are the standard ways to detect IME composition in progress
- All terminal output readers (SSH, Unix local, Windows local) must use `UTF8SafeBuffer` to handle multi-byte character splitting at buffer boundaries

### Version 2.37 - Drag & Drop Fix & Debug Log Tab (2026-02-09)

**Critical Bug Fix — Wails WKWebView Drop Event Never Fires:**

This was a complex debugging session that uncovered a fundamental limitation of Wails on macOS.

When `DragAndDrop.DisableWebViewDrop: true` is set in `main.go`, the native WKWebView (`WailsWebView.m:performDragOperation`) intercepts ALL drop operations at the Objective-C level. This means the JavaScript `drop` event **never fires** for ANY drag operation — not for OS-level Finder drags, and not for in-app HTML5 drags between components. Only `dragend` fires.

**Symptoms observed:**
1. Dragging files from file manager to terminal: overlay appeared ("拖动文件以插入路径到终端") but releasing mouse did nothing
2. Dragging files between file managers (remote↔local): no upload/download occurred
3. File manager "drag-over" highlight CSS stayed permanently after releasing mouse

**Root cause analysis path:**
- Initially suspected `dataTransfer.getData()` returning empty (WKWebView restriction) → partially true but not the core issue
- Added shared memory module (`dragState.ts`) to bypass `dataTransfer` → still didn't work
- Added in-app **Log Tab** for debugging (since Wails production builds have no DevTools) → revealed that `drop` event NEVER fires, only `dragend` fires
- Read Wails source code (`WailsWebView.m`) and confirmed: `disableWebViewDragAndDrop=true` causes native layer to handle drop, JS `drop` event is suppressed

**Solution — `dragend` + shared memory + `elementFromPoint`:**
1. **`dragState.ts`**: Shared module stores `DragPayload` (source + path) and `DragTarget` (terminal / local-fm / remote-fm)
2. **`dragStart`**: File managers call `setDragPayload()` to store path in memory
3. **`dragover`** (capture phase on Content): Uses `document.elementFromPoint()` to detect which zone cursor is over, calls `setDragTarget()`
4. **`dragend`** (window capture phase): Reads payload + target from shared memory, dispatches action:
   - `terminal` → `WriteToTerminal()` with escaped path
   - `local-fm` + remote source → `DownloadFile()` (SFTP download)
   - `remote-fm` + local source → `UploadFile()` (SFTP upload)
5. **Visual state cleanup**: File managers listen for `dragend` on `window` to clear `dragOver` CSS state, since `drop` (which normally clears it) never fires

**Other fixes:**
- `ConnectSSH()` was being called with a host string instead of full `SSHConfigEntry` object, causing `json: cannot unmarshal string` error
- Fixed in both `handleCreateSession` (clicking server) and `connectSessionIfNeeded` (lazy connect on tab activation)

**Debug Log Tab (permanent feature):**
- Built-in Log tab added to main UI for debugging without browser DevTools
- `dlog()` utility: logs to in-memory buffer (500 max) + console.log
- Copy All button for easy log export
- All drag-and-drop code uses `dlog()` for traceability

**Files Changed:**
- **New**: `frontend/src/utils/dragState.ts`, `frontend/src/utils/debugLog.ts`, `frontend/src/components/log/LogTab.tsx`
- **Modified**: `App.tsx`, `TerminalTab.tsx`, `LocalFileManager.tsx`, `FileManager.tsx`, `AGENTS.md`

**Key Lessons:**
- In Wails with `DisableWebViewDrop: true`, NEVER rely on JavaScript `drop` events — they will never fire
- Always use `dragend` + shared memory as the drop mechanism in Wails apps
- `document.elementFromPoint()` is the reliable way to detect drop target in this environment
- An in-app debug log viewer is essential for Wails apps since WKWebView has no DevTools in production
- `ConnectSSH` accepts `SSHConfigEntry` object, not a host string — always check Go function signatures

### Version 2.26 - Terminal Drag & Drop Support

**功能**：在 Terminal 界面支持拖拽文件，自动将文件绝对路径插入到终端。

**关键技术点 - Wails 拖拽最佳实践：**

1. **全局 OnFileDrop 管理**：
   - Wails 的 `OnFileDrop` 是**全局唯一回调**，只能注册一次
   - 在 App.tsx 统一注册，根据活动 tab 通过 `CustomEvent` 分发

2. **⭐ CSS Drop Target 标记** - **核心关键点**：
   - **必须在 CSS 中添加 `--wails-drop-target: drop` 属性**
   - `OnFileDrop(callback, true)` 第二个参数 `true` 表示只响应带此属性的元素
   - **没有此属性，`OnFileDrop` 不会被触发** ❌
   - 示例：
     ```css
     .terminal-content { --wails-drop-target: drop; }
     .editor-tab-container { --wails-drop-target: drop; }
     ```

3. **Wails OnFileDrop 拦截浏览器事件**：
   - Wails OnFileDrop 会拦截浏览器原生 onDrop 事件
   - 需要手动分发 `app:clear-drag-state` 事件清除拖拽状态

- `App.tsx` - 全局 OnFileDrop 管理和事件分发

### Version 2.20 - Terminal Session Dedup & Tab-Switch Flicker Fix

**问题 1：打开终端出现两份登录日志（duplicate PTY）**

三层原因导致同一个 session 创建了两个 PTY：
1. 前端 `handleCreateSession` 无防抖，快速点击可触发重复连接
2. 后端 `ssh_manager.go` 用秒级时间戳 (`time.Now().Unix()`) 生成 session ID，同秒内碰撞
3. 后端 `StartTerminalSession` 用 `RLock` 做存在检查，两个并发请求同时通过（TOCTOU 竞态）

**修复（三层防御）：**
- **前端** `TerminalTab.tsx`：`connectingHostsRef` (Set) 阻止同一 host 重复发起连接
- **后端** `ssh_manager.go`：session ID 改用纳秒精度 `time.Now().UnixNano()`
- **后端** `websocket_handler.go`：`StartTerminalSession` / `StartLocalTerminalSession` 改用 **写锁** (`termSessionMu.Lock()`)，获取锁后立即放占位符 `terminalSessions[sessionID] = nil`，彻底消除 TOCTOU

**问题 1.1：React StrictMode 双挂载仍导致重复**

StrictMode unmount→remount 时 cleanup 函数重置了 `sessionStartedRef`，导致 guard 失效。

**修复**：cleanup 中 **不再重置** `sessionStartedRef.current = null`，让 ref 跨 StrictMode 周期保留。

**问题 2：切换终端 Tab 时之前的终端"闪烁"（看起来重连了）**

原因：用 `display: none` 隐藏非活跃 tab → 容器尺寸变为 0×0 → 切回时 ResizeObserver 触发 `fit()` → 发送 `ResizeTerminal` → 后端 SIGWINCH → shell 重绘。

**修复（参考 electerm 项目 `session.styl`）：**

| 改动 | 文件 | 要点 |
|------|------|------|
| CSS | `TerminalTab.css` | 非活跃 tab 改用 `position: absolute; visibility: hidden; pointer-events: none`，保持容器尺寸不变 |
| CSS | `TerminalTab.css` | 活跃 tab 加 `.session-active { visibility: visible; pointer-events: auto }` |
| TSX | `TerminalTab.tsx` | 渲染时用 class `session-active` 替代 inline `display` 样式；传 `isActive` prop 给 `Terminal` |
| TSX | `Terminal.tsx` | 新增 `isActive` prop + `isActiveRef`；`handleResize` 内 `if (!isActiveRef.current) return` 跳过非活跃 tab |
| TSX | `Terminal.tsx` | 新增 `lastDimensionsRef`，仅在尺寸真正变化时才发 `ResizeTerminal`，避免冗余 SIGWINCH |
| TSX | `Terminal.tsx` | tab 变为活跃时自动 `focus()` + `handleResize()` 补偿隐藏期间的窗口大小变化 |

**问题 3：`Cannot access 'handleResize' before initialization`**

`const` 声明的暂时性死区（TDZ）—— `useEffect` 引用 `handleResize` 的位置在 `useCallback` 定义之前。

**修复**：将 `isActive` 同步的 `useEffect` 移到 `handleResize = useCallback(...)` **之后**。

**核心经验：**
- `display: none` 会导致 xterm 容器尺寸归零，切回时触发 resize 风暴 → 用 `visibility: hidden` + 绝对定位保持尺寸
- 后端防重复必须用 **写锁 + 占位符**，读锁存在 TOCTOU 窗口
- React StrictMode cleanup 不要重置用于防重复的 ref
- `useCallback` / `const` 有 TDZ，`useEffect` 引用它们必须放在声明之后

**Files Changed:**
- `frontend/src/components/terminal/Terminal.tsx` — isActive prop, handleResize guard, lastDimensionsRef, TDZ fix
- `frontend/src/components/terminal/TerminalTab.tsx` — CSS class 切换, isActive prop 传递
- `frontend/src/components/terminal/TerminalTab.css` — absolute + visibility:hidden 替代 display:none
- `websocket_handler.go` — 写锁 + 占位符防 TOCTOU
- `ssh_manager.go` — 纳秒级 session ID

```go
// internal/app/ssh_manager.go - ListFiles function
// Before: Used ls command via ExecuteCommand
// After: Uses SFTP client directly
func (a *App) ListFiles(sessionID string, path string) ([]FileInfo, error) {
    sftpClient, err := getSFTPClient(sessionID)
    if err != nil {
        return nil, err
    }
    defer sftpClient.Close()
    
    // Resolve ~ to home directory
    if path == "" || path == "~" {
        homeDir, err := sftpClient.Getwd()
        if err != nil {
            return nil, fmt.Errorf("failed to get remote home directory: %v", err)
        }
        path = homeDir
    }
    
    // Read directory via SFTP
    entries, err := sftpClient.ReadDir(path)
    if err != nil {
        return nil, fmt.Errorf("failed to read remote directory: %v", err)
    }
    
    // Convert to FileInfo
    var files []FileInfo
    for _, entry := range entries {
        if entry.Name() == "." || entry.Name() == ".." {
            continue
        }
        files = append(files, FileInfo{
            Name:    entry.Name(),
            Size:    entry.Size(),
            Mode:    entry.Mode().String(),
            ModTime: entry.ModTime().Format(time.RFC3339),
            IsDir:   entry.IsDir(),
        })
    }
    return files, nil
}
```
